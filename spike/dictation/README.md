# PROTOTYPE: voice dictation spike

Throwaway. Lives on the `spike-voice-dictation` branch and never merges. It
answers section 7 of `docs/research/voice-dictation.md` ("What the spike must
measure") for the **web** and **Linux desktop** paths. Android, Windows, and
accuracy on Andy's own recordings are not covered yet (see "Not settled").

## Verdict

Moonshine streaming works on both paths, fast enough, with zero main-thread
jank, but **four things the research assumed are wrong**:

1. **Spanish output has no capitals and no punctuation.** Tiny and Small
   Spanish both return lowercase text with no commas, periods, `¿` or `¡`
   ("la primera parte del ingenioso hidalgo don quijote de la mancha"). Both
   English models return cased, punctuated text. This is not documented
   anywhere in Moonshine's repo or the model cards. The research's plan to
   "rely on the model's own case and punctuation" holds for English only.
   Spanish needs a punctuation and truecasing pass before v1.
2. **The npm package `@moonshine-ai/moonshine-wasm@0.1.5` is stale.** Its WASM
   was built from an older core: its catalog has no Spanish streaming model,
   and it rejects the current model layout (`frontend.model.ort` +
   `frontend.weights.ort`). The WASM in the GitHub release
   (`moonshine-voice-wasm.tar.gz`, v0.1.5) is current and works. Vendor that,
   not npm.
3. **The package's worker cannot be bundled by Vite.** `SttWorkerHost` breaks
   three ways under Maibuk's Vite config (below). Maibuk needs its own worker
   (`dictation-worker.ts`, 150 lines), which also lets the AudioWorklet post
   straight to the worker so the main thread never touches audio.
4. **Default settings miss the latency bars.** With defaults, the first
   partial lands about 1 s after speech starts on every path. Two settings fix
   it: `transcription_interval=0.2` (a core option, default 0.5) plus, on the
   web, the JS `Stream` `updateInterval=0.2` (a second, separate gate). On
   native, `MOONSHINE_ORT_SINGLE_THREAD=1` is required: without it ONNX
   Runtime spins 5 to 7 cores for Tiny English.

Also confirmed, from the Tauri shell on this machine (WebKitGTK,
`AppleWebKit/605.1.15`):

- `getUserMedia` → `NotAllowedError`. Webview mic capture is out on Linux; Rust
  capture is the path.
- `SharedArrayBuffer` is **false** even with `crossOriginIsolated === true`.
  The threaded WASM cannot run in WebKitGTK at all, so desktop must be native.
- No `SpeechRecognition`, no WebGPU, no Long Tasks API in WebKitGTK.

## Results against section 7

Final settings: `transcription_interval=0.2`, web `updateInterval=0.2`,
native `MOONSHINE_ORT_SINGLE_THREAD=1`. Audio replayed in real time through the
real capture path (AudioWorklet on the web, the same channel cpal feeds on
native). Machine: Linux x86_64, 16 threads, X11. Generated by `report.py` from
`results/*.json`.

(energy detector in `onsets.py`), not from Moonshine's `line.startTime`, which
sits about 0.24 s earlier because of VAD look-behind. Only lines that begin at

## What production code needs (from building this)

- **Vendor the release WASM, not npm.** `fetch-models.mjs` does it.
- **Own the worker.** Vite, given `SttWorkerHost`:
  - copies `new URL("./stt-worker.js", import.meta.url)` as a raw asset, so its
    `import "./transcriber.js"` 404s;
  - inlines `new URL("./", import.meta.url)` (`moonshineWasmBaseUrl`) as a
    base64 `data:` URL of `index.js`;
  - rewrites the Emscripten pthread spawn to `self.location.href`.

  `dictation-worker.ts` loads the glue from its own `?url` asset and passes it
  to Emscripten as `mainScriptUrlOrBlob`, with `locateFile` pointing at the
  hashed `.wasm`. `SttWorkerHost` also has no `setContext`; the own worker
  calls `Transcriber.setContext` directly.
- **Bundle two `.so` files on Linux.** `libmoonshine.so` and
  `libonnxruntime.so.1` must ship with the app with an `$ORIGIN`-relative
  rpath. A dependency crate's `rustc-link-arg` rpath does not reach the Tauri
  binary (the spike runs it with `LD_LIBRARY_PATH`).
- **`libasound2-dev` becomes a Linux build dependency** (cpal always pulls
  `alsa-sys`). The spike uses a pkg-config shim (`native/alsa-shim.sh`)
  because this machine has only the runtime library.
- **Null `lines` pointer.** With no lines yet, `moonshine_transcribe_stream`
  returns `lines == NULL`; `slice::from_raw_parts(NULL, 0)` is undefined
  behaviour. The debug Tauri build caught it; the release build hid it. Any
  real binding must guard it.
- **The Channel is not a bottleneck:** Rust to page in under 1.4 ms, max.
- **Spanish needs punctuation and truecasing** before v1. Options not yet
  evaluated; the research rejected a 1.1 GB punctuation model when it assumed
  the ASR punctuated.

## Not settled

- Android (device, `adb`, Kotlin plugin, `RECORD_AUDIO`). Needs Andy's phone.
- Accuracy: WER and fillers on Andy's own Spanish and English recordings.
- Windows.
- Typing latency inside WebKitGTK and on Android (no automated key input into
  WebKitGTK here).
- A live-speech mic run: capture was verified with real samples (-93 dBFS
  noise floor over 4 s), but nobody spoke. Run the mic command below and talk.
- Web offline after first visit (Cache API / service worker) and the 25 MiB
  Cloudflare per-file limit for Tiny English's 32.6 MB decoder.
- Production Tauri (`tauri://` protocol, `app.security.headers`). Irrelevant
  for desktop now that the WASM path is out there.

## Run it

All commands from the repo root. Models (≈330 MB) and runtimes go into
gitignored folders.

```bash
node spike/dictation/fetch-models.mjs          # models + WASM + Linux lib

# Web page (mic or file), Chromium with COOP/COEP
VITE_BUILD_TARGET=web npx vite --config spike/dictation/vite.config.ts   # http://localhost:5199
# Measured runs on the production build
VITE_BUILD_TARGET=web npx vite build --config spike/dictation/vite.config.ts
VITE_BUILD_TARGET=web npx vite preview --config spike/dictation/vite.config.ts &   # :5198
SPIKE_INTERVAL=0.2 SPIKE_QUERY="opt.transcription_interval=0.2" SPIKE_TAG="-ti0.2" \
  node spike/dictation/measure.mjs

# Linux native CLI
eval "$(spike/dictation/native/alsa-shim.sh)"
cargo build --release --manifest-path spike/dictation/native/Cargo.toml
MOONSHINE_ORT_SINGLE_THREAD=1 spike/dictation/native/target/release/dictation-spike \
  spike/dictation/public/models/small-streaming-es small mic 60 transcription_interval=0.2
spike/dictation/native/matrix.sh tiny-streaming-en spike/dictation/public/audio/two_cities_16k.wav 0.5 0.2

# Inside the Maibuk Tauri shell (separate identifier; an installed Maibuk is untouched)
spike/dictation/native/tauri-run.sh "auto=1&model=small-streaming-es&source=quijote_es_16k.wav&opt.transcription_interval=0.2"

python3 spike/dictation/report.py              # rebuild the tables above
```

Test audio: `two_cities_16k.wav` (Moonshine's `test-assets`, LibriVox) and the
first 120 s of LibriVox *Don Quijote* vol. 1, file 02, converted to 16 kHz
mono. `fetch-models.mjs` downloads both into `public/audio/` (needs `ffmpeg`
for the Spanish one).
